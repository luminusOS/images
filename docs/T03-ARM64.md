# T03: Fedora 45 ARM64 UEFI proof

At the start of each run, Skopeo reads the Fedora 45 manifest indexes for the
allowlisted bootc and builder repositories once. T03 requires exactly one
`linux/arm64` child in each index, records each raw-index hash, then inspects
the selected child by digest to verify its config platform. The resulting
immutable references are used for the rest of the run. Missing, ambiguous, or
invalid registry data fails closed; there is no mutable-tag fallback.

The `resolved-inputs.json` artifact records the UTC resolution time, source
tags, selected child digests, raw-index hashes, and available image version
labels. This policy is limited to this proof. It does not change
`config/versions.env`, production image definitions, or publish an image or
package.

The workflow builds a small qcow2 and boots it on a native ARM64 GitHub-hosted
runner through AArch64 UEFI in QEMU. Its derived bootc image carries an explicit
GPT, EFI, ext4 boot, and ext4 root layout for Image Builder.

The job only runs for the public repository on
`proof/t03-arm64-uefi`. It can start from a push to that exact branch or a
manual dispatch selected on that branch. It has read-only repository
permissions, uses the standard public ARM runner, and retains its evidence for
one day. QEMU uses `-cpu host` with KVM and `-cpu max` with bounded TCG. The
qcow2 is used only on the disposable runner; the workflow records its SHA-256
and virtual/physical file sizes, then deletes it. The artifact contains logs
and metadata only. It excludes the disk image, an ISO, an OCI image, and
packages.

The guest writes a start marker with a fresh per-run nonce, then checks
`aarch64`, Fedora 45, and `/sys/firmware/efi` before writing the matching pass
marker. A complete serial transcript is required. The host architecture,
QEMU exit status, and both resolved image config platforms are checked; the
builder container also verifies Fedora 45 before installing packages. An early
QEMU exit fails. The evidence artifact contains the serial
proof, QEMU diagnostics, disk hash and sizes, concise runner/build metadata, and
a build log capped at 1 MiB. The boot proof has not yet run on the hosted ARM
runner. The earlier hosted attempt failed while resolving the builder's pinned digest,
before entering the build container, so no image build or boot has yet been
proven. This proof does not qualify a final ISO, GNOME, Sirius, or an
installation flow.

Run the local checks with:

```bash
/usr/bin/python3 -m unittest discover -s tests -p 'test_t03_arm64_proof.py' -v
bash -n .github/scripts/t03-arm64-proof.sh
```

To resolve and inspect the current public Fedora 45 ARM64 inputs without
building an image, run:

```bash
bash .github/scripts/t03-arm64-proof.sh --resolve-inputs /tmp/t03-resolved-inputs.json
```

The host build/boot itself requires a native ARM64 machine and is intentionally
not emulated on x86. The runner inventory and public-repository pricing are
documented by [GitHub](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).
Image Builder's bootc qcow2 input and configuration behavior are documented
[here](https://osbuild.org/docs/user-guide/image-descriptions/bootc/qcow2/) and
[here](https://osbuild.org/docs/developer-guide/projects/image-builder/advanced/bootc/sources-of-configuration/).
Podman's storage configuration is documented
[here](https://docs.podman.io/en/stable/markdown/podman.1.html#environment-variables).
